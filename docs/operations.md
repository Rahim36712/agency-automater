# Operations, recovery and privacy

One `npm start` command runs the local helper and n8n. Both use loopback only. A private header credential protects helper mutations; browser-origin requests and unexpected Host headers are rejected. Only one helper process may hold the journal. n8n schedules enqueue durable jobs; jobs execute serially. Repeat schedules reuse an already queued/running task. Queued work continues after restart. A job that was running during a crash becomes `interrupted`; rerun it from n8n/CLI. Its individual outreach intents remain durable.

Check `reports/YYYY-MM-DD.json`, REPORTS and ACTIVITY LOG for errors. The CLI prints a job ID and outcome. Sheets failure/auth failure keeps local audit events and suppression; new outreach fails closed until Sheets can be read. Gmail reads and idempotent Sheets row PUTs have bounded retries. Gemini availability failures instead try lower approved free-tier models once each: 3.8 Flash → 3.5 Flash-Lite → 3.1 Flash-Lite, starting at the configured model. A failed model enters a persisted five-minute cooldown (one hour for model-not-found); later requests skip it until cooldown expires. Every attempted model consumes the same global throttle/daily budget. Local cap, authentication and invalid input cannot be bypassed by switching. Invalid/blocked/truncated AI output produces a visible error and no draft. If all approved lower models fail, the job reports temporary unavailability without inventing output; fallback is not a guarantee of quota or service availability. Fallback attempts and selected models are logged locally and flushed to ACTIVITY LOG on ordinary task runs.

Draft creation is a non-idempotent API operation. Before the only POST, the helper saves a deterministic operation key (`Lead ID:Stage`), unique Message-ID and visible Reference. A lost response leaves the operation `uncertain`. Run `recover` and `reconcile` after restoring connectivity. Existing matching drafts and sent messages are synced to Sheets. If neither can be identified, leave the operation blocked and inspect Gmail manually. This release intentionally provides no automatic rearm, resend or unsafe journal-delete command.

If you delete a Gmail draft, the operation still blocks automatic regeneration. If you manually send a previously prepared draft after the contact opts out, the helper cannot undo the send. Check SUPPRESSION and replies before manually sending. Existing unsent drafts addressed to an opted-out contact must be deleted in Gmail by you. The daily pending-draft count reflects CRM operations; a manually deleted draft may remain counted until you mark its CRM status for manual attention. Sent reconciliation remains authoritative for follow-up timing.

SUPPRESSION is mirrored from Sheets into the local journal and local entries are restored to Sheets on every run. Deleting a sheet row or reimporting a lead cannot remove local opt-outs. Every incoming reply creates a durable email-level stop; uncertain replies do not resume automatically. To change an opt-out or resume a relationship, use a separately reviewed process after explicit contact consent. Do not erase the journal to achieve this.

During active automation avoid sorting, deleting or moving CRM rows while a job is writing. Pause schedules, wait for jobs to finish, then edit structure. Ordinary cell reviews are supported; approvals are reread before draft creation. Only this helper should automate writes to the CRM. RAW Sheets writes prevent scraped text from becoming a spreadsheet formula. Website access pins a validated public DNS address, refuses redirects to other domains/private addresses, respects robots, limits bytes/time/pages and never executes site JavaScript. Website terms still require your review before enabling Research Allowed.

Back up after shutting down both processes. Keep **the whole `.data/` directory**, `.env`, source/workflows, the pinned package lock, and an export of the Google Sheets CRM together. This includes SQLite journal files, n8n's database and its encryption/config key, Google tokens and suppression. Store backups privately and encrypted using your own backup tool. Restoring an older journal can omit later opt-outs or outreach attempts; recover the latest suppression/operations and reconcile Gmail before allowing any drafts. Never run two copies against the same CRM/account.

`.env`, Google tokens, journals, evidence snapshots, logs and reports are ignored by Git. OAuth tokens are plaintext locally with user-folder access controls; the project does not claim disk encryption. Evidence snapshots contain bounded public company text, and the journal stores email addresses/message IDs needed for suppression and recovery. Minimize collected contacts. Google Gemini free-tier inputs can be used to improve products: do not send confidential customer data. The optional uncertain-reply AI call sends only the current, unquoted reply (max 4,000 characters); disable it by replacing that call with manual review if your privacy needs require it. The safe rule outcome already remains manual review.

The daily report is deterministic and saves locally before Sheets sync. A Google outage can make the scheduled report task fail while the local file survives. Current-state counts include pending drafts and meetings; event counts cover the Karachi calendar day. Errors caught on a lead remain logged even when the overall batch completes. Successful sent events are deduplicated by operation ID, and reply events by Gmail message ID.

## Commercial email review

Before any manual send, check accurate sender/recipient/subject, clearly commercial purpose, one real observation, a service you can deliver, valid physical postal address, and working reply-based opt-out. Keep opt-out handling available and monitor it while the laptop is off. The FTC explains that CAN-SPAM applies to commercial business-to-business email and requires honoring opt-outs within 10 business days, with the mechanism available for at least 30 days after sending. This application suppresses detected opt-outs on its next successful scan, so use Gmail manually during downtime. Also review applicable recipient-country and Pakistan obligations before outreach. The implementation assists compliance; it does not establish legal permission for a particular campaign.

Source: [FTC CAN-SPAM compliance guide](https://www.ftc.gov/business-guidance/resources/can-spam-act-compliance-guide-business), checked 2026-10-11. No project acceptance, payment authorization, billable cloud action or external email send is automated.
